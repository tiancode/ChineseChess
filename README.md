# 中国象棋（Xiangqi）

一个用 Rust 编写、带图形界面的中国象棋程序，可与内置 AI 对弈。
界面基于跨平台 GUI 框架 [`egui`/`eframe`](https://github.com/emilk/egui)，
AI 通过一个可插拔的接口实现，方便日后替换为更强的引擎。

---

## 功能特性

- **完整规则**：车、马、炮、相/象、仕/士、将/帅、兵/卒的全部合法走法，
  包含「马腿」「象眼」「炮架（隔子吃）」「过河兵」「将帅对脸（飞将）」等限制。
- **胜负判定**：将死、困毙（无棋可走判负）、被将军提示。
- **重复局面规则**：按 **CCA/亚洲规则**裁决（非一律判和）——循环中一方
  长将/长捉则该方判负，双方互将/互捉或纯位置重复才判和；另连续 60 回合
  无吃子判和（详见下文「已知限制 / 简化」）。
- **人机对弈**：可选择执红（先手）或执黑（后手）；选黑时棋盘自动翻转，
  己方始终在下方。
- **可选 AlphaZero 引擎与「AI 对战」模式**：除内置 AlphaBeta 外，可为
  AI 方选用基于神经网络的 **AlphaZero** 引擎，或让两台引擎自动对弈
  （AlphaZero 需 Python + PyTorch，详见下文）。
- **AI 难度**：1–5 级，随时可调（AlphaBeta 对应搜索深度/时间预算，
  AlphaZero 对应 MCTS 模拟数）。
- **棋盘交互**：点击选子、走子，高亮显示选中棋子、可走点、上一步、被将军的将/帅。
- **对局辅助**：新对局、悔棋（自动回退 AI 的应着）、认输、着法记录列表、
  坐标标注（列 A–I，行 1–10）。
- **存档**：对局以 JSON 保存 / 载入（载入后仍能正确判断重复局面）。
- **AI 后台运行**：引擎在独立线程中思考，界面不卡顿。

## 环境要求

- Rust 工具链（已在 **Rust 1.95** 上验证），通过 `rustup` 或系统包安装。
- 一款支持中文（CJK）的字体。程序会自动在常见路径查找：
  - Linux：`/usr/share/fonts/noto-cjk/NotoSansCJK-Regular.ttc` 等
  - macOS：`PingFang.ttc` / `STHeiti`
  - Windows：`msyh.ttc` / `simsun.ttc`

  若找不到，程序仍可运行，但棋子文字可能显示为方块（终端会打印一行警告）。

## 操作说明

| 操作 | 说明 |
|---|---|
| 选子 / 走子 | 先点己方棋子（高亮），再点高亮的目标点落子 |
| 新对局执棋 | 选「红（先手）」或「黑（后手）」后点 **开始新对局** |
| AI 难度 | 拖动滑条 1–5（越大棋力越强、思考越久） |
| 悔棋 | 回退到你上一手之前（会一并撤销 AI 的应着） |
| 认输 | 立即判负 |
| 保存 / 载入 | 在文件名输入框填路径后点击对应按钮 |
| 着法记录 | 右侧列表，格式如 `炮 H3→E3`（列 A–I，行 1–10） |

界面右侧顶部实时显示对局状态：轮到谁、将军、将死/困毙/认输/和棋等。

## AI 说明与替换方法

内置引擎 (`src/ai/search.rs`)：

- **搜索**：迭代加深 + Alpha-Beta（PVS 零窗口）+ **置换表**（Zobrist
  键）+ **静态搜索**（叶子处只搜吃子至局面平静，消除送子/地平线效应）。
- **走法排序**：置换表着法 → MVV-LVA 吃子 → 杀手着法 → 其余。
- **评估**：子力价值（车 1000、炮 500、马 450、仕/相 200、兵 100）
  + 车/炮/马/兵专用 piece-square 位置表。
- **重复局面感知**：搜索中遇到历史局面或当前搜索路径上的局面按和棋
  处理——领先时不会自陷三次重复，劣势时也能找到求和。
- **难度**：1–5 映射为 (最大搜索深度, 每步时间预算)，迭代加深取两者
  先到者：1→(4, 0.2s) 2→(6, 0.8s) 3→(10, 3s) 4→(18, 15s)
  5→(28, 90s)。高档把深度上限抬得远高于时钟所及，使**时间预算成为
  实际限制**，故最难每步约思考 1.5 分钟。AI 在后台线程运行，界面不卡顿。

### AlphaZero 引擎（可选）

除内置 AlphaBeta 外，本程序可调用一个基于 **AlphaZero**（自我对弈训练的
深度神经网络 + 蒙特卡洛树搜索 MCTS）的引擎。网络与训练代码在独立的
[`alphazero/`](alphazero/) 子项目（PyTorch，纯 Python 实现，其走法规则
已与 Rust 引擎的 perft 对齐）；训练、调参与运行方式见 `alphazero/README.md`。

- **如何启用**：右侧「对战模式」选「人机对战」或「AI 对战」，并在引擎下拉框
  为相应一方选择 **AlphaZero**。Rust 端会自动启动一个常驻的 Python 伴生
  进程（`alphazero/serve.py`，通过 stdin/stdout 行分隔 JSON 通信）做推理。
- **运行前提**：本机已装 Python 与 PyTorch，且有训练好的模型权重。可用
  环境变量定位：`XIANGQI_PYTHON`（解释器）、`XIANGQI_AZ_DIR`（`alphazero/`
  路径）、`XIANGQI_AZ_CKPT`（权重文件）。自检：
  `python -m alphazero.serve --selftest`。
- **难度**：1–5 映射为 **MCTS 模拟数**（1→100 2→300 3→800 4→2000
  5→4000）。与 AlphaBeta 不同，这里没有时间预算——每步耗时 ≈ 模拟数 ×
  伴生进程推理速度（取决于 CPU/GPU 与模型大小）。
- **降级**：若 Python / PyTorch / 权重缺失导致伴生进程无法启动，界面会
  给出提示并停止自动走子；改用内置 AlphaBeta 即可继续对弈。

### 替换为更强的 AI

只需实现 `Engine` trait，并在 `make_engine()` 中返回你的实现，**其余代码无需改动**：

```rust
pub trait Engine: Send {
    fn name(&self) -> String;
    fn best_move(&mut self, state: &GameState) -> Option<Move>;
}
```

界面的线程调度、难度滑条、合法性校验都会自动适配新引擎。

## 工程质量

- `cargo test`：**34** 个默认测试全绿（另有 2 个 `#[ignore]` 测试:节点
  基准与 AlphaZero 伴生进程)——规则/perft、CCA 重复局面（长将/
  长捉判负、纯重复判和）、引擎战术、以及端到端 UI 逻辑（翻转点击的
  精确逆映射、选子走子、悔棋退两手、认输、存档往返、AI 自动应着）。
- `cargo clippy --all-targets`：**零告警**。
- 引擎跨步常驻（`Arc<Mutex>`），**置换表跨手复用**；难度变更或新对局
  才重建。
- 基准（release，本机参考值）：引擎严格遵守时间预算，节点数随难度
  单调增长——难度 1→5 开局约 1.4 万→70 万节点（0.12s→4.5s），
  约 100–190 knps。运行：
  `cargo test --release engine_benchmark -- --ignored --nocapture`。

## 已知限制 / 简化

- **重复局面按 CCA/亚洲规则裁决**（非一律判和）：循环中一方**长将**或
  **长捉**则该方判负；一将一捉以**长将方负**（长将为重）；双方都长将、
  都长捉、或双方皆为闲着的纯位置重复才判和。
  - *已实现并经测试的核心*：长将分类与判负、双方互将/纯重复判和、
    长捉无根子判负、被充分保护之子（等价兑换）不算捉、兵/帅作为追击
    方按闲。
  - *文档化的近似*：长捉用 1 步静态交换近似判定；「献/兑/拦、复杂的
    一将一捉变体」等各规则版本有分歧之处采用 **CCA 通行解释**，未逐条
    形式化验证。
  - *引擎*：搜索内部**精确处理长将**（长将方按负分），长捉不在搜索内
    裁决（按和）；权威结果始终以对局规则 `GameState::status` 为准。
- 无开局库；搜索为全量重算 Zobrist（正确性优先），knps 中等但时间
  受控、界面不卡。
- 存档仅校验版本、数据长度与着法下标范围，不做局面合法性深检。
- 找不到 CJK 字体时棋子以字母（K/A/E/H/R/C/P）显示并给出提示，
  核心可玩；但右侧中文菜单仍需 CJK 字体方可正常显示。
